Un archivo HTML que genera modelos 3D descargables como STL. Sin servidor, sin dependencias instaladas, sin base de datos. Todo ocurre en el browser del usuario. Esta guía descompone cada bloque del código, explica por qué está construido así y qué puedes modificar.

Arquitectura

Stack técnico

La app usa exactamente una librería externa: Three.js. Todo lo demás — CSS, lógica, UI, exportación — es JavaScript puro del browser. La única dependencia se carga desde una CDN pública, lo que significa que el archivo funciona offline si ya fue cargado una vez.

¿Por qué un solo archivo?
Portabilidad total. No hay npm install, no hay build, no hay servidor. Abres el HTML en cualquier browser y funciona. Esto lo hace ideal para herramientas personales y para publicar en GitHub Pages.
TecnologíaRolPor qué
Three.js 0.160 Renderizado 3D, geometría, exportación STL La librería 3D más madura para el browser. Tiene todo lo necesario incluido.
Import maps Resolver módulos ES sin bundler Permite usar import from 'three' sin npm ni webpack.
CSS Variables Sistema de diseño Centraliza todos los colores y valores. Cambiar un color cambia toda la app.
Canvas API Superficie de renderizado Three.js escribe directamente en un elemento canvas del HTML.
Bloque 01

Variables CSS

Toda la paleta de colores vive aquí. Es el "tema" de la app. Cambiar estos valores cambia el aspecto visual completo sin tocar nada más.

01 :root — Sistema de colores
▶
El selector :root define variables globales accesibles en todo el CSS con la sintaxis var(--nombre). Es como declarar constantes en código — si cambias --accent en un lugar, todos los botones, sliders y valores numéricos cambian de color automáticamente.

El esquema es oscuro por diseño: fondos casi negros con un acento verde-lima eléctrico. Este contraste extremo hace que los números y controles resalten sin esfuerzo visual.
CSS
:root {
  /* Fondos — tres niveles de profundidad */
  --bg: #0d0d0c;        /* Fondo principal — casi negro */
  --bg-panel: #161614;   /* Sidebar y panels */
  --bg-elev: #1d1d1a;    /* Elementos elevados (hover) */

  /* Texto */
  --ink: #f5f1e8;        /* Texto principal — blanco cálido */
  --ink-dim: #8a857a;    /* Labels y texto secundario */

  /* Acentos */
  --accent: #d4ff3a;      /* Verde lima — color principal */
  --accent-warm: #ff7a3d; /* Naranja — hover de botón secundario */

  /* Bordes */
  --line: #2a2a26;        /* Separadores y bordes */
  --grid: rgba(212,255,58,0.06); /* Grid de fondo — muy sutil */
}
--accent
El color dominante. Cambia esto y cambia toda la personalidad visual.
Ej: #00ffcc para cian, #ff3a6e para rosa
--bg / --bg-panel
Para versión clara: --bg: #f8f6f0, --bg-panel: #ffffff, --ink: #1a1a18
Solo cambiando estos 3 tienes modo claro
Bloque 02

Three.js setup

La inicialización del motor 3D. Aquí se crean los tres objetos fundamentales sin los cuales nada se ve: la escena, la cámara y el renderer.

02 Escena, cámara y renderer
▶
La escena es el contenedor de todo — objetos, luces, grilla. Piénsala como el "mundo".

La cámara PerspectiveCamera simula visión humana: los objetos lejanos se ven más pequeños. Los parámetros son el ángulo de visión (45°), el aspect ratio, y los planos de recorte (qué tan cerca y lejos se renderiza).

El renderer es el motor que convierte la escena en píxeles. antialias: true suaviza los bordes — sin esto los bordes tienen dientes de sierra. alpha: true hace el fondo transparente para que el CSS del body se vea a través.

shadowMap activa las sombras. PCFSoftShadowMap es el algoritmo de sombras suaves — más costoso que las sombras duras pero mucho más realista.
JavaScript
// Los tres objetos fundamentales
const scene = new THREE.Scene();
scene.background = null; // transparente — el CSS maneja el fondo

const camera = new THREE.PerspectiveCamera(
  45,   // FOV: ángulo de visión en grados
  1,    // aspect ratio (se actualiza en resize)
  0.1, // near: no renderiza más cerca de esto
  2000 // far: no renderiza más lejos de esto
);
camera.position.set(200, 180, 260); // posición inicial de la cámara

const renderer = new THREE.WebGLRenderer({
  canvas,
  antialias: true,  // bordes suaves
  alpha: true       // fondo transparente
});
renderer.shadowMap.enabled = true;
renderer.shadowMap.type = THREE.PCFSoftShadowMap; // sombras suaves
FOV (45)
Ángulo de visión. Menor = más "telefoto" (objetos parecen más planos). Mayor = más distorsión tipo gran angular.
Prueba: 35 para más elegante, 60 para más dramático
camera.position
Posición inicial de la cámara en el espacio 3D (x, y, z). Y es la altura.
Prueba: set(0, 300, 0) para vista cenital
Bloque 03

Iluminación — la magia del 3D

La iluminación es lo que hace que el modelo se vea sólido y tridimensional. Forja usa un esquema de tres luces clásico del cine — key, rim y fill — más una luz ambiente.

03 Esquema de tres luces
▶
AmbientLight — ilumina todo por igual, sin dirección. Evita que las sombras sean completamente negras. Con intensidad 0.35 es sutil.

Key light (luz principal) — la luz dominante. Viene desde arriba y el lado. Genera las sombras principales. castShadow: true la hace proyectar sombras.

Rim light (contraluz) — posicionada detrás y al lado opuesto. Su color #d4ff3a — el mismo verde del acento CSS — crea un halo que separa el objeto del fondo. Esto es lo que hace que el modelo "flote".

Fill light (relleno) — naranja suave desde abajo, intensidad 0.15. Solo suaviza las sombras duras, casi no se nota directamente.
JavaScript
// Luz ambiente — base suave para todo
scene.add(new THREE.AmbientLight(0xffffff, 0.35));

// Key light — luz principal con sombras
const key = new THREE.DirectionalLight(0xffffff, 1.2);
key.position.set(120, 200, 80);
key.castShadow = true;
scene.add(key);

// Rim light — contraluz con color acento
const rim = new THREE.DirectionalLight(0xd4ff3a, 0.4);
rim.position.set(-100, 50, -100); // lado opuesto a la key
scene.add(rim);

// Fill light — naranja suave desde abajo
const fill = new THREE.DirectionalLight(0xff7a3d, 0.15);
fill.position.set(80, -50, 100);
scene.add(fill);
Color del rim light
Cambiar 0xd4ff3a cambia el halo del objeto. Es lo que le da la identidad cromática al preview 3D.
Prueba: 0x3ab8ff para halo azul
Intensidades
Key: 1.2 (dominante), Rim: 0.4, Fill: 0.15. Subir rim acerca la estética a producto de lujo.
Rim en 0.8 = efecto dramático
Bloque 04

Material — cómo se ve la superficie

El material define cómo reacciona la superficie a la luz. MeshPhysicalMaterial es el más realista de Three.js — simula propiedades físicas reales como roughness (rugosidad) y clearcoat (barniz).

04 MeshPhysicalMaterial
▶
color: #e8e2d0 — un blanco hueso cálido. No blanco puro, porque el blanco puro con luces direccionales se ve artificial.

roughness: 0.55 — qué tan rugosa es la superficie. 0 = espejo perfecto, 1 = completamente mate. 0.55 es como plástico fino o cerámica mate.

metalness: 0.1 — cuánto se comporta como metal. 0.1 le da un leve brillo metálico sin hacer el objeto verse de metal.

clearcoat: 0.2 — capa de barniz encima. Agrega un segundo lóbulo de reflexión, como si el objeto tuviera una capa de laca. ClearcoatRoughness 0.6 hace ese barniz mate, no brilloso.
JavaScript
const trayMaterial = new THREE.MeshPhysicalMaterial({
  color: 0xe8e2d0,          // blanco hueso cálido
  roughness: 0.55,          // semi-mate
  metalness: 0.1,           // leve brillo metálico
  clearcoat: 0.2,           // capa de barniz
  clearcoatRoughness: 0.6, // barniz mate
});
color
El color del objeto. Cambiarlo es trivial y transforma completamente la estética.
0x2a2a2a = carbón oscuro
0x4a90d9 = azul PLA
roughness + metalness
Para simular materiales reales de impresión 3D:
PLA mate: roughness: 0.8, metalness: 0
PETG: roughness: 0.3, metalness: 0.05
clearcoat
Para simular resina o acabado brillante: subir a 0.8 con clearcoatRoughness: 0.1
Resina: clearcoat: 0.9, clearcoatRoughness: 0.05
MeshStandardMaterial
Si el render es lento en hardware modesto, reemplaza Physical por Standard — menos parámetros, más rápido, muy similar visualmente.
Quita clearcoat y clearcoatRoughness
Bloque 05

Geometría — el corazón del proyecto

Aquí es donde el código construye el modelo 3D. Es la parte más interesante y la más original — no usa primitivas de Three.js sino que construye las formas desde cero usando extrusión de perfiles 2D.

05a roundedRectShape — el perfil con esquinas
▶
Esta función dibuja un rectángulo con esquinas redondeadas en 2D usando THREE.Shape — el equivalente 3D de un path SVG. Las esquinas se hacen con quadraticCurveTo — curvas de Bézier cuadráticas.

La línea crítica: r = Math.min(r, Math.min(w, h) / 2 - 0.01) — limita el radio para que nunca exceda la mitad del lado más corto. Sin esto, si pones un radio muy grande la forma se deforma.

→

05b buildTray — ensamblado de piezas
▶
La bandeja se construye como un conjunto de piezas separadas que luego se fusionan:

1. Base — el fondo sólido. Siempre existe.
2. Paredes — se crean con un truco elegante: un shape exterior con un shape interior como "hole" (agujero). ExtrudeGeometry extruye esa forma anular, creando las paredes huecas de una sola operación.
3. Divisores — rectángulos delgados extruidos dentro del espacio interior.

Modo placa — si el alto es menor o igual a la base, la app detecta que es una placa sólida y desactiva paredes y divisores automáticamente. Esto es un comportamiento emergente, no un switch manual.

mergeGeometries — al final fusiona todas las piezas en una sola geometría. Esto es crítico para el STL — si no se fusiona, el archivo tendría geometrías separadas que algunos slicers no manejan bien.
JavaScript — la lógica del modo placa
// Si alto <= base, es una placa sólida
const isPlate = p.alto <= p.base;

// Las paredes solo existen si hay altura real
if (!isPlate && wallHeight > 0.1) {
  // Shape exterior con hole interior = pared hueca
  const wallShape = roundedRectShape(p.largo, p.ancho, p.radio);
  const innerShape = roundedRectShape(
    p.largo - 2*p.pared,
    p.ancho - 2*p.pared,
    innerR
  );
  wallShape.holes.push(innerShape); // el hueco
}
¿Por qué extrusión y no primitivas?
Three.js tiene BoxGeometry, pero una caja es sólida. Una bandeja tiene paredes huecas, esquinas redondeadas y divisores. Construirla con extrusión de shapes 2D permite cualquier forma imaginable — solo cambia el Shape.
Bloque 06

OrbitControls — por qué el movimiento es tan suave

Esta es la respuesta a tu pregunta. El movimiento suave no es magia — son tres líneas de configuración de OrbitControls.

06 Damping — la física del freno
▶
enableDamping: true — activa la inercia. Sin esto, cuando sueltas el mouse la rotación se detiene instantáneamente. Con damping, la cámara desacelera gradualmente, como si estuviera en un líquido viscoso.

dampingFactor: 0.08 — qué tan rápido frena. Es un valor entre 0 y 1. Valores bajos (0.03–0.08) = muy suave, inercia larga. Valores altos (0.3–0.5) = frena rápido, casi sin inercia.

La condición crítica: el damping solo funciona si llamas a controls.update() en cada frame del loop de animación. Si lo olvidas, la cámara no se mueve.
JavaScript
const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;      // activa la inercia
controls.dampingFactor = 0.08;     // suavidad del freno
controls.target.set(0, 15, 0);    // punto hacia donde mira la cámara

// En el loop de animación — OBLIGATORIO para el damping
function animate() {
  controls.update(); // ← sin esto no hay suavidad
  renderer.render(scene, camera);
  requestAnimationFrame(animate);
}
dampingFactor
El parámetro de suavidad. Es lo primero que ajustar si quieres más o menos inercia.
0.03 = muy fluido, lento
0.15 = más responsivo
target
El punto al que orbita la cámara. Se actualiza dinámicamente cuando cambia el alto del modelo.
Se recalcula en updateMesh()
requestAnimationFrame — el loop de animación no corre a velocidad fija. El browser lo sincroniza con la pantalla (60fps, 120fps según el monitor) y lo pausa cuando la pestaña está oculta. Esto es eficiente y es por qué no consume CPU innecesariamente.
Bloque 07

UI — sliders conectados al modelo

El sistema de UI es deliberadamente simple: sliders HTML nativos conectados al modelo 3D mediante event listeners. Sin frameworks, sin state management.

07 Event listeners y reactividad
▶
Cada slider tiene un ID. Un array con todos los IDs permite registrar los listeners en un loop en lugar de repetir código 8 veces.

Cuando el usuario mueve un slider, el listener llama a updateMesh() que: lee todos los parámetros, destruye el mesh anterior, construye uno nuevo, y lo agrega a la escena. Todo en milisegundos.

Destruir y reconstruir en lugar de modificar la geometría existente es una decisión de simplicidad. Modificar geometrías en Three.js es más complejo. Para este caso de uso — modelos pequeños, interacción fluida — el enfoque funciona perfectamente.
JavaScript
// Un loop para registrar todos los listeners
const inputs = ['largo','ancho','alto','pared','base','radio','divx','divy'];

inputs.forEach(id => {
  const el = document.getElementById(id);
  el.addEventListener('input', () => {
    // Actualiza el número visible en el label
    valEl.textContent = el.step.includes('.')
      ? parseFloat(el.value).toFixed(1)
      : el.value;
    updateMesh(); // reconstruye el modelo
  });
});
Bloque 08

Exportar STL

La exportación STL ocurre completamente en el browser — sin servidor, sin upload. El archivo se genera en memoria y se descarga directamente.

08 STLExporter y descarga local
▶
STLExporter de Three.js convierte el mesh actual en un archivo STL binario. binary: true genera formato binario — más pequeño y más compatible con slicers que el formato ASCII.

El truco de la descarga: se crea un Blob (objeto binario en memoria), se genera una URL temporal con URL.createObjectURL, se crea un link invisible, se hace click programáticamente, y luego se libera la URL. Todo en el browser, cero servidores.

El nombre del archivo incluye las dimensiones: bandeja_150x100x30_r8.stl — así el archivo es auto-descriptivo.
JavaScript
const exporter = new STLExporter();
const stl = exporter.parse(currentMesh, { binary: true });

// Crear archivo en memoria y descargar
const blob = new Blob([stl], { type: 'application/octet-stream' });
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = `bandeja_${p.largo}x${p.ancho}x${p.alto}_r${p.radio}.stl`;
a.click();
URL.revokeObjectURL(url); // liberar memoria
¿Por qué binario y no ASCII?
El STL ASCII es texto legible pero puede ser 5–10x más grande. Los slicers modernos (Bambu Studio, PrusaSlicer, Cura) manejan binario perfectamente y es el formato estándar para intercambio.
